# CARE 지식 수집기 (장애이력 자동 수집 모바일 웹)

장애 알림 SMS 원문(`[Web발신]` 형식, 예: 신한카드 TMS 온라인 비즈니스오류 임계치 초과 알림)을 그대로 붙여넣거나, 직접 입력하거나, 스크린샷을 올리면 정형 데이터(IF아이디, 서비스코드, 오류율, 거래건수, 수신자 등)를 자동으로 추출하고, 과거 유사 장애 사례를 참고한 AI 초안(장애원인 후보/조치내용/재발방지책)을 생성해 장애이력 마스터 시트에 적재하는 모바일 최적화 웹 애플리케이션입니다.

> ⚠️ **AI 기능 관련 중요 안내**: 본 프로젝트는 서버가 없는 순수 정적 웹사이트입니다. 브라우저 JS에서 Gemini 등 인증이 필요한 외부 LLM/Vision API를 직접 호출하면 API 키가 클라이언트에 노출되는 보안 위반이 되므로, 플랫폼 정책상 구현할 수 없습니다. 대신 아래처럼 **동일한 사용자 효과를 내는 정적사이트 호환 대체 기술**을 적용했습니다: ① LLM 파싱 → **Levenshtein 편집거리 기반 퍼지 라벨 매칭**, ② AI 심층 추천 → **과거 이력 기반 규칙 추론**, ③ RAG 유사사례 검색 → **로컬 유사도 스코어링**, ④ Vision AI → **Tesseract.js(브라우저 로컬 OCR, API 키/서버 불필요)**.

## 🎯 프로젝트 목표
- 현업이 수신한 장애 SMS를 수작업으로 엑셀 정리하는 시간을 최소화
- 장애이력을 표준 스키마로 축적하여 향후 LLM 학습/RAG 파이프라인 재료로 활용
- 조직 전체의 누적 목표(1,000건) 대비 진행률을 실시간으로 시각화
- 업무코드/서비스코드/담당자명/수신자명 등 민감정보는 **어떤 경로로도 원본이 저장·노출되지 않도록** 보안 마스킹을 다층적으로 적용

---

## ✅ 현재 완료된 기능

### 1. SMS 입력 탭 (`#tab-collector`)
**입력 모드 3종 지원** — 상단 토글로 전환:
- **SMS 붙여넣기**: 실제 수신 문자 원문을 그대로 붙여넣어 파싱
- **직접 입력(템플릿)**: SMS 원문을 받지 못했거나 수기로 등록해야 할 때, SMS 원문과 **완전히 동일한 항목 구성의 입력 폼**(알림 정보/거래 정보/비교 데이터/현재 현황/수신 정보)에 값을 직접 입력하여 등록. 입력값은 내부적으로 SMS 원문과 동일한 `[Web발신] ▶ 라벨 : [값]` 템플릿 텍스트로 재구성된 뒤 **기존 SMS 파싱 엔진에 그대로 통과**하므로, 자동 마스킹·중복검사·AI초안·원문 sanitize 로직이 두 입력 경로에 걸쳐 100% 동일하게 적용됩니다(로직 이중 구현 없음, 보안 정책 우회 불가).
- **스크린샷(OCR)**: 문자 캡처 화면·모니터링 대시보드 스크린샷을 업로드하거나 화면에서 **Ctrl+V로 붙여넣기**하면 **Tesseract.js(브라우저 로컬 OCR)**가 이미지 속 텍스트를 인식(진행률 표시)하여 편집 가능한 텍스트로 보여주고, 그 텍스트를 기존 파싱 엔진에 그대로 통과시켜 SMS 붙여넣기와 동일하게 처리합니다. **이미지는 서버로 전송되지 않고 브라우저 내부에서만 처리**됩니다.

#### 🧠 ① 퍼지(fuzzy) 라벨 매칭 — 정규식 한계 보완
라벨 앞뒤 공백/줄바꿈이 다르거나 오타(예: "업무코드"→"업무코트")가 있어도, **Levenshtein 편집거리**로 가장 유사한 라벨을 찾아 값을 추출합니다(`fuzzyExtractValue`/`extractField`). 대괄호가 없는 변형 양식도 콜론 뒤 텍스트를 값으로 인식하는 폴백 로직으로 대응합니다. 정확한 대괄호 패턴이 실패했을 때만 동작하는 2차 방어선입니다.

#### 🔍 ③ 과거 유사 장애 사례 자동 매칭 (RAG-like 로컬 유사도)
SMS/직접입력/OCR로 파싱이 완료되는 즉시, 현재 마스터 리스트를 대상으로 IF아이디·에러코드·업무코드·대외기관 일치 여부와 알림제목 키워드 중복도를 가중합산해 0~100% **유사도 점수**를 계산합니다(`findSimilarIncidents`). 유사도 40% 이상인 상위 3건을 "과거 유사 장애 사례" 패널에 조치자·부서·해결방법과 함께 표시해, 신입 담당자도 과거 이력을 즉시 참고할 수 있습니다.

#### ✨ ② AI 초안 심층 추천 (규칙 + 과거 이력 기반)
`draftKnowledge()`가 위에서 찾은 **검증완료된 과거 유사사례**를 최우선으로 반영하고, 대외기관 연계/지연 키워드/기본 규칙을 조합해 **확신도(confidence) 순 최대 3개 원인 후보**와 **단계별(1→2→3) 조치 가이드**를 생성합니다. "AI 초안" 영역에 초안의 근거(어떤 과거 사례를 참고했는지)와 후보 원인 목록이 함께 표시됩니다.

실제 수신 문자 양식(`[Web발신]` + `▶ 라벨 : [값]` 대괄호 구조)을 그대로 파싱합니다.

```
[Web발신]
[신한카드] TMS 온라인 비즈니스오류 임계치 초과 알림
▶ IF아이디 : [HPG00760]
▶ IF명 : [[개인]해외이용 할부전환 신청]
▶ 업무코드 : [ITL]
▶ 서비스코드 : [SITL18519A]
▶ 대외기관 : [-]
▶ 거래일자 : [20260808]
▶ 거래시간 : [0850~0950](1시간)
▶ 거래집계일시 : [2026-08-08 09:53:02]
▶ 비교일수 : [5](휴일)동시간대
▶ 비교기간평균거래건수 : [31]
▶ 비교기간평균오류건수 : [8]
▶ 비교기간평균오류율 : [25.81]%
▶ 오류율임계치 : [67]%
▶ 현재거래건수 : [46]
▶ 현재오류건수 : [31]
▶ 현재오류율 : [67.39]%
▶ 메시지 수신자 : [신정은, 김찬수, 김원상, 김지수, 박남호]
▶ 메시지 발생일시 : [2026-08-08 10:03:47]
```

- **대괄호 깊이 카운팅 파서**: `IF명 : [[개인]해외이용 할부전환 신청]`처럼 값 내부에 또 다른 `[...]`가 포함된 경우에도 정확한 바깥쪽 닫는 괄호까지 잘라내어 값을 온전히 추출 (`extractBracketValue`)
- **알림 제목 자동 추출**: `[Web발신]` 다음 줄에서 선행 태그(`[신한카드]` 등)를 제거한 제목만 추출 (`extractAlertTitle`)
- **내부관리코드 자동 분류**: 제목 키워드(임계치 초과/지연/오류)로 `E-TMS-THRESHOLD` / `E-TMS-DELAY` / `E-TMS-ERROR` / `E-TMS-ALERT` 자동 분류
- **약 20개 필드 자동 추출**: IF아이디/IF명/업무코드/서비스코드/대외기관/거래일자/거래시간/거래집계일시/비교일수/비교기간평균거래건수/비교기간평균오류건수/비교기간평균오류율/오류율임계치/현재거래건수/현재오류건수/현재오류율/수신자/메시지발생일시 등
- **대외기관 인지형 AI 초안**: 대외기관이 명시된 경우 해당 기관명을 반영한 원인/조치 문구를 자동 생성, 없는 경우 지연/오류 키워드 기반 일반 문구 생성 (`draftKnowledge`)
- 파싱 결과는 등록 전 **AI 초안 항목(원인/조치/재발방지책/부서/담당자) 수정 가능**
- **실제 양식 샘플 3종** 즉시 불러오기: `임계치초과(대외기관없음)` / `대외기관 연계오류` / `야간배치 오류` (SMS 붙여넣기 모드)
- **중복 이력 감지**: 동일 IF아이디 + 거래집계일시(`agg_datetime`)가 이미 마스터에 있으면 경고 배너 표시
- **임시저장(Draft)**: 입력 중인 SMS 원문을 localStorage에 자동 저장 → 새로고침해도 유지
- **요약 복사**: 파싱 결과를 클립보드에 텍스트로 복사 (마스킹된 값만 포함)

### 🔒 내부 보안 마스킹 정책
사내 보안 정책상 **업무코드 / 서비스코드 / 담당자명 / 메시지 수신자명**은 원본 값이 시스템(DB·엑셀·화면·SMS 원문 저장본 포함)에 그대로 저장·노출되지 않아야 합니다.

| 항목 | 마스킹 규칙 | 예시 |
|---|---|---|
| 업무코드 | 첫 글자만 노출 | `ITL` → `I**` |
| 서비스코드 | 앞 4자리만 노출 | `SITL18519A` → `SITL****` |
| 담당자명 | 첫 글자만 노출 | `김선호` → `김**` |
| 메시지 수신자(다수) | 인원별 첫 글자만 노출, 목록 유지 | `신정은, 김찬수` → `신**, 김**` |

**적용 시점 및 방식 (다층 방어)**
1. **추출 즉시 마스킹**: SMS 파싱 시점에 업무코드/서비스코드/수신자를 추출 즉시 마스킹 처리(`maskBizCode`/`maskSvcCode`/`maskRecipients`)하여, 원본 문자열은 파싱 함수 내부에서만 잠시 존재하고 화면 상태(state)나 Table API로 절대 전달되지 않습니다.
2. **SMS 원문 자체도 마스킹 처리 (`sanitizeRawSms`)**: 원문 텍스트 안에도 업무코드/서비스코드/수신자 원본이 그대로 포함되어 있으므로, `error_msg`로 저장하기 전에 해당 대괄호 구간을 마스킹된 값으로 치환한 **정화된 텍스트만** 저장합니다. 원본 raw 텍스트는 파싱 함수 스코프를 벗어나지 않습니다.
3. **UI 입력단 보호**: 담당자 입력란은 포커스를 벗어나는 즉시(blur) 마스킹 표시로 전환됩니다.
4. **등록/저장 시점 재마스킹(이중 안전장치)**: 등록(`handleRegister`) 및 수정 저장(`handleSaveEdit`) 시점에 업무코드/서비스코드/담당자/수신자를 한 번 더 마스킹 함수에 통과시켜, 화면 조작(개발자도구 등)으로 readonly 속성을 우회하더라도 원본이 저장되지 않습니다.
5. **UI 잠금 표시**: 마스터 리스트 수정 화면에서 서비스코드·수신자·담당자·SMS 원문 필드는 **읽기전용(자물쇠 아이콘 표시)**으로 처리하여 마스킹을 우회한 원본 재입력이 불가능합니다. SMS 원문(`error_msg`)은 저장 시에도 기존 저장값으로 강제 고정되어 절대 변경되지 않습니다.
6. **Idempotent 마스킹**: 마스킹 함수는 이미 마스킹된 값을 다시 처리해도 동일한 결과를 반환하므로, 여러 단계에서 재마스킹을 적용해도 값이 훼손되지 않습니다.
7. 엑셀 내보내기, 요약 복사, 대시보드 등 **모든 출력 경로에 마스킹된 값만** 흐르도록 구성되어 있습니다.

### 2. 마스터 탭 (`#tab-master`)
- 등록된 전체 장애이력을 카드형 리스트로 표시 (Table API 실시간 연동) — 알림제목/IF아이디·서비스코드·대외기관/내부관리코드/오류율(임계치) 표시
- **검색**: IF아이디, IF명, 내부관리코드, 담당자, 관리번호, 서비스코드, 알림제목, 대외기관 통합 검색
- **다중 필터 패널** (검색창 옆 슬라이더 아이콘 클릭으로 펼치기/접기, 필터 적용 중일 땐 점 표시): **상태**(등록대기/검증중/검증완료), **담당부서(팀)**, **업무코드**, **대외기관** — 모두 현재 마스터 리스트에 존재하는 값으로 자동 채워지는 드롭다운, **IF아이디**(자유 텍스트 검색). 모든 필터는 AND 조건으로 동시 적용되며, "필터 초기화" 버튼으로 한번에 해제 가능
- **카드 클릭 → 수정 모달**: 20개 필드 수정 (마스킹 필드는 잠금 표시, 수정 불가)
- **삭제 기능**: 확인 다이얼로그 후 삭제 (되돌리기 불가 경고)

### 3-1. AI 탭 (`#tab-ai`) — 시연용 신규 기능 5종
> ⚠️ 아래 기능들도 실제 Gemini API 호출이 아닌, **동일한 사용자 경험을 로컬 로직으로 재현한 데모 구현**입니다(정적 사이트는 인증 필요 외부 API를 안전하게 호출할 수 없음).

- **🔍 AI 자연어 지식 검색**: "코스콤 관련 장애 원인이 뭐였지?" 같은 질문을 입력하면 질문에서 키워드를 추출해 마스터 이력을 검색하고, 가장 관련도 높은 사례를 자연어 답변 문장으로 조합해 보여줍니다. 샘플 질문 칩 제공.
- **📊 AI 주간/월간 인사이트 리포트**: `AI 인사이트 리포트` → `리포트 생성` 클릭 시 마스터 데이터를 집계(최다 발생 IF, 취약 대외기관, 재발위험 부서, 검증완료율)해 Executive 요약 문장으로 생성.
- **✨ AI 표준 문구 정화(Smart Proofreader)**: 파싱 결과 카드의 장애원인/조치내용/재발방지책 각 입력란 옆 `AI 교정` 버튼 클릭 시, 구어체·비표준 표현을 격식체로 간단 치환·정리.
- **🤖 Gemini AI 정밀 진단**: 파싱 결과 카드 상단의 `Gemini AI 정밀 진단 실행` 버튼 클릭 시, 오류율·과거 유사사례를 재종합해 원인/조치/방지책 초안을 다시 생성(내부적으로 `draftKnowledge`+`findSimilarIncidents` 재실행).
- **📢 팀 메신저 공유 리포트 복사**: 파싱 결과 카드의 노란색 말풍선 아이콘 버튼 클릭 시, 슬랙/카카오톡에 바로 붙여넣을 수 있는 장애 요약 템플릿을 클립보드에 복사.

## 🔗 기능 진입점 (경로/파라미터)
정적 SPA(단일 `index.html`) 구조이며, URL 파라미터 없이 탭 내부 상태로 화면 전환됩니다.

| 화면 | 접근 방법 |
|---|---|
| SMS 입력 | `index.html` 접속 시 기본 화면, 하단 탭 "SMS입력" |
| 마스터 리스트 | 하단 탭 "마스터" 클릭 |
| 현황 대시보드 | 하단 탭 "현황" 클릭 |
| 엑셀 내보내기 | 헤더 우측 다운로드 아이콘 클릭 |

### 데이터 API (RESTful Table API, 내부적으로 사용)
- `GET tables/incidents` — 전체 장애이력 목록 조회
- `POST tables/incidents` — 신규 장애이력 등록 (마스킹 적용된 값만 전송)
- `PATCH tables/incidents/{id}` — 장애이력 수정 (마스킹 필드는 재마스킹 후 전송)
- `DELETE tables/incidents/{id}` — 장애이력 삭제

## 🚧 아직 구현되지 않은 기능 (향후 개발 제안)
1. **실제 LLM/Vision API 연동**: 현재 ①③④는 정적사이트에서 구현 가능한 대체 기술(퍼지매칭/로컬 유사도/Tesseract.js OCR)로 구현되어 있습니다. 실제 Gemini 등 LLM/Vision API(사용자 API 키 + 서버 필요)를 연동하면 문맥 이해 기반 파싱 정확도와 원인분석 품질이 한층 높아질 수 있습니다.
2. **다중 사용자 로그인/권한 관리**: 담당자별 로그인, 부서별 접근 제어 (서버 인증이 필요한 영역)
3. **SMS 자동 수신 연동**: 실제 문자 수신함과 연동한 자동 수집 (모바일 OS 권한/서버 연동 필요)
4. **첨부파일(로그) 업로드**: 장애 근거자료 첨부 기능 (스크린샷은 OCR 입력 경로로 이미 지원됨)
5. **알림 기능(Push/이메일)**: 신규 등록/미검증 건에 대한 담당자 알림
6. **엑셀 일괄 업로드(Import)**: 기존 보유 이력 대량 등록
7. **다양한 발신사/양식 지원**: 현재는 신한카드 TMS `[Web발신]` 양식에 최적화되어 있으며, 타 시스템/타 발신사 양식이 추가로 필요하면 라벨 패턴을 추가 등록하는 방식으로 확장 가능
8. **진짜 임베딩 기반 RAG**: 현재 유사사례 매칭은 필드 일치·키워드 중복도 기반 로컬 스코어링입니다. 벡터DB/임베딩을 쓰면 의미적으로 더 유사한 사례까지 찾아낼 수 있습니다.

### AI 기능 구현 방식 요약
| 사용자 요청 | 이상적 구현 | 정적사이트 제약으로 실제 적용한 대체 구현 |
|---|---|---|
| ① LLM 기반 유연한 SMS 파싱 | Gemini API 등에 텍스트 던져 JSON 추출 | Levenshtein 편집거리 기반 퍼지 라벨 매칭 (`fuzzyExtractValue`) |
| ② AI 심층 원인/조치 추천 | 유사 이력 + LLM으로 원인 3가지·단계별 가이드 생성 | 과거 유사사례(③) + 규칙 기반 추론으로 확신도순 후보 3개·단계별 가이드 생성 (`draftKnowledge`) |
| ③ 과거 유사 장애 RAG 매칭 | 임베딩/벡터DB 검색 | 필드 일치도 + 제목 키워드 중복도 가중합산 로컬 유사도 스코어링 (`findSimilarIncidents`) |
| ④ 스크린샷 Vision AI 파싱 | Vision API로 이미지 텍스트 인식 | Tesseract.js 브라우저 로컬 OCR (서버 전송 없음) |
